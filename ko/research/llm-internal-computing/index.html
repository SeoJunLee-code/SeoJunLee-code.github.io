LLM Internal Computing

LLM 내부 결정론적 컴퓨터 검증

재현 · 부분AI 보조 구현독립 검토 없음저장소: 공개 예정
연구 질문LLM 안에 결정론적 컴퓨터를 넣는 두 업스트림 프로젝트의 단위 테스트가 고정 커밋에서 통과하는가?
재현만 했습니다. 두 업스트림 프로젝트의 단위 테스트를 고정 커밋에서 돌렸습니다. 통과·실패 개수와 원인만 보고하며 성능 수치는 없습니다. 업스트림이 주장하는 회로, riscv-tests, 벤치마크는 재현하지 않았습니다.

질문

공개 프로젝트 QwenPU와 Qwenputer는 언어모델 안에 결정론적 컴퓨터를 넣습니다. 이를 바탕으로 무언가 만들기 전에, 고정한 버전에서 그들의 단위 테스트가 통과하는지 확인했습니다.

출처 표기

업스트림 프로젝트의 저자는 divagr18입니다(qwenpu 커밋 5af1fc0, qwenputer 커밋 bec1a0c). 이 저장소는 그들의 코드를 복사하지 않고 커밋만 가리킵니다. 고정한 커밋은 클론한 시점의 최신 커밋이며, 업스트림 저자가 고른 버전이 아닙니다.

첫 실행 (컨테이너) 실측

프로젝트수집통과건너뜀실패오류미완료
QwenPU2822462211–3
Qwenputer5624794911158

실패와 오류의 원인은 네 가지입니다. 업스트림 코드와 맞지 않는 테스트, 없는 입력 파일, 메모리 부족으로 강제 종료된 프로세스, 시간 제한입니다. 이 결과만으로 업스트림 구현이 맞다 틀리다를 판단할 수 없습니다.

재실행 실측

  • 코랩(RAM 13GB)에서는 컨테이너가 끝내지 못한 메모리 부담이 큰 테스트 6개가 모두 통과했습니다
  • 시간 제한에서 잘렸던 테스트 파일 하나는 이후 끝까지 돌았습니다: 113개 중 113개 통과
  • 다른 파일은 더 긴 제한에서도 멈췄습니다: 6개 중 3개 통과, 3,000초 제한에 걸림. 제한을 더 늘리면 달라지는지는 미검증입니다

한계

  • 단위 테스트만 했으며 성능 수치는 없고, 업스트림 설계가 소개대로 동작한다는 주장도 하지 않습니다
  • 첫 실행 표는 컨테이너 실행 기록이며 재실행 뒤에 고쳐 쓰지 않았습니다
  • 일부 실패는 업스트림 변경 때 남은 테스트 때문일 수 있으나, 이는 판단이며 확인된 원인이 아닙니다

검증과 AI 활용

개수는 프로젝트의 테스트 보고서와 대조했습니다. AI 보조 구현. 독립적인 검토는 없습니다. 테스트는 컨테이너와 코랩에서 돌렸습니다.
