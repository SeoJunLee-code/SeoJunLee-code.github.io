H1

Majority-vote backfire

Hypothesis RefutedAI-assisted implementationNo independent review
Research questionWhen a model sometimes answers correctly, does majority voting fail on more than half of those problems?
Refuted in all 4 conditions by the decision rule written in the experiment code.

Question

Asking a model to solve the same problem many times and taking the most common answer (majority voting) usually raises accuracy. But on a problem where the right answer shows up only sometimes, a wrong answer can become the majority. We call that backfire. H1 says: among problems where the model is sometimes right, majority voting is wrong on more than half.

Method

  • Models: Qwen2.5-1.5B-Instruct, Qwen2.5-3B-Instruct; datasets: GSM8K and MATH-500 (levels 3–4 only)
  • 120 problems per condition, 16 samples per problem, temperature 0.7, at most 1024 new tokens
  • Non-degenerate problem: some but not all samples are correct (always-right and always-wrong problems are excluded)
  • Backfire: the share of non-degenerate problems where the majority answer is wrong; 95% interval from a problem-level bootstrap (10,000 resamples)
  • Decision rule: refuted if the backfire 95% CI upper bound < 0.50; supported if the lower bound > 0.50; otherwise inconclusive

In every condition the upper bound of the interval is below 0.50. Among problems where the model is sometimes right, majority voting is wrong on 14%–21%, not more than half.

Part of the backfire is unavoidable Measured

Given how the votes split, some wrong majorities cannot be avoided (an arithmetic floor). The excess above that floor has a 95% interval whose lower bound is above zero in three conditions (0.009–0.022) and 0.000 in the fourth.

Difficulty effect Measured

Comparing the harder dataset with the easier one: 4 pairs, 0 with an interval that excludes zero. All were inconclusive; the effect of difficulty is not settled.

Limitations

  • Two models, one temperature, 16 votes per problem; non-degenerate problems number only 55–106 per condition, so intervals are wide
  • The 1024-token cap truncated some solutions (cap reached in 0%–9% of samples)
  • MATH-500 uses levels 3–4 only; an earlier level-5 run is not included
  • No pre-registration document was found. The hypothesis wording is read from the decision rule in the code, so the result is labelled by that rule and not as pre-registered

Verification and AI use

The figures on this page were generated from the project's analysis files by script and checked by tests against the same files. AI-assisted implementation; this page does not itemise who wrote which lines. No independent review.
